# Система управления объявлениями для модерации

## Описание проекта

Система управления объявлениями — это веб-приложение для модерации, которое позволяет:

- **Просмотр и фильтрация объявлений** — список объявлений с множественными фильтрами (статус, категория, цена, поиск по названию), сортировкой и пагинацией
- **Детальный просмотр** — полная информация об объявлении с галереей изображений, характеристиками товара, данными о продавце и историей модерации
- **Модерация объявлений** — одобрение, отклонение или возврат на доработку с указанием причины
- **Навигация между объявлениями** — быстрый переход к предыдущему/следующему объявлению для эффективной модерации
- **Аналитика и статистика** — подробная статистика работы модератора с графиками активности, решений и категорий
- **Тёмная/светлая тема** — переключение темы оформления с сохранением выбора
- **URL-синхронизация фильтров** — все параметры фильтрации сохраняются в URL для возможности делиться ссылками

## Запуск проекта

1. Клонируйте репозиторий командой

```bash
git clone [ссылка_на_репозиторий]
```

2. Перейдите в папку с сервером, установите зависимости и запустите приложение:

```bash
# Переход в директорию сервера
cd tech-int3-server
# Установка зависимостей
npm install
# Запуск сервера
npm start
# Или запуск в режиме разработки с автоматической перезагрузкой
npm run dev
```

Сервер будет доступен по адресу `http://localhost:3001`.

3. Откройте другой терминал. Перейдите в папку с клиентов, установите зависимости и запустите приложение:

```bash
# Переход в директорию клиента
cd client
# Установка зависимостей
npm install
# Запуск клиента в режиме разработки
npm run dev
```

Приложение будет доступно по адресу `http://localhost:5173`.

**Примечание**: Убедитесь, что порты 3001 (backend) и 5173 (frontend) свободны.

### Переменные окружения

По умолчанию приложение использует `http://localhost:3001/api/v1` в качестве адреса API.

Для изменения адреса API создайте файл `.env` в корне папки `client` и укажите свой адрес:

```env
VITE_API_HOST=http://localhost:3001/api/v1
```

## Стек технологий

### Core

- **React 19** — современная библиотека для построения UI
- **TypeScript** — типизация для повышения надежности кода
- **React Router 7** — декларативная маршрутизация на клиенте
- **Vite** — быстрый сборщик нового поколения для разработки и продакшена

### Управление состоянием и работа с API

- **Redux Toolkit** — современный подход к управлению глобальным состоянием
- **RTK Query** — мощное решение для работы с API с автоматическим кешированием, инвалидацией и ретраями

### UI и стилизация

- **HeroUI (NextUI)** — современная компонентная библиотека на основе React Aria
- **TailwindCSS 4** — utility-first CSS фреймворк для быстрой стилизации (Нужна для HeroUI)
- **Framer Motion** — библиотека для плавных анимаций (Нужна для HeroUI)
- **Lucide React** — набор иконок
- **Recharts** — библиотека для построения графиков и диаграмм

### Дополнительные библиотеки

- **use-debounce** — хук для дебаунса

### Инструменты разработки

- **ESLint** — линтинг кода с настроенными правилами для React и TypeScript
- **Prettier** — автоматическое форматирование кода

## Архитектура

Проект организован по **слоевой архитектуре** с четким разделением ответственности:

```
src/
├── api/                    # Слой API - работа с backend
│   ├── baseApi.ts          # Базовая конфигурация RTK Query
│   ├── advertisementsApi.ts # API для работы с объявлениями
│   └── statsApi.ts         # API для получения статистики
│
├── store/                  # Слой управления состоянием
│   ├── store.ts            # Конфигурация Redux Store
│   ├── reducers/           # Redux слайсы
│   │   └── themeSlice.ts   # Управление темой приложения
│   ├── middlewares/        # Кастомные middleware
│   │   └── themeMiddleware.ts # Синхронизация темы с localStorage
│   └── utils.ts            # Утилиты для работы со store
│
├── pages/                  # Страницы приложения
│   ├── AdvertisementListPage.tsx  # Список объявлений (/list)
│   ├── AdvertisementItemPage.tsx  # Детальная страница (/item/:id)
│   ├── ModerStatsPage.tsx         # Статистика модератора (/stats)
│   └── NotFoundPage.tsx           # 404 страница
│
├── components/             # Слой UI - переиспользуемые компоненты
│   ├── Example.tsx          # Различные компоненты
│   ├── skeletons/          # Skeleton-загрузчики
│   └── errors/             # Компоненты отображения ошибок
│
├── lib/                    # Переиспользуемый код
│   ├── hooks/              # Кастомные хуки
│   │   ├── useAdsParsingSearchParams.ts  # Парсинг URL параметров
│   │   ├── useAdsUpdateSearchParams.ts   # Обновление URL параметров
│   │   └── usePreservedQuery.ts          # Сохранение query при навигации
│   ├── types.ts            # TypeScript типы и интерфейсы
│   ├── constants.ts        # Константы приложения и маппинг данных
│   └── utils.ts            # Утилитарные функции
│
├── App.tsx                 # Корневой компонент с роутингом и провайдерами
└── main.tsx               # Точка входа приложения
```

**Разделение ответственности** — каждый слой имеет свою четкую задачу:

- `api/` — работа с backend, определение endpoints
- `store/` — управление глобальным состоянием
- `components/` — UI компоненты
- `pages/` — композиция компонентов для страниц
- `lib/` — переиспользуемая логика и утилиты

## Управление состоянием

Приложение использует **Redux Toolkit** с **RTK Query** для эффективного управления состоянием:

### Глобальное состояние (Redux)

- **Theme** — хранение и управление темой оформления (светлая/тёмная)
- Middleware для синхронизации темы с `localStorage`
- Применение классов темы к DOM при изменении

### API State (RTK Query)

RTK Query автоматически управляет состоянием для:

- **Кеширование** — данные сохраняются в кеше и переиспользуются
- **Автоматическая инвалидация** — при изменении данных (модерация) автоматически обновляются связанные запросы
- **Ретраи** — до 2 автоматических повторных попыток при ошибках сети
- **Оптимистичные обновления** — немедленное обновление UI с последующей синхронизацией
- **Управление загрузкой** — автоматические флаги `isLoading`, `isFetching`, `error`

## Особенности реализации

### 1. URL-синхронизация фильтров

Все параметры фильтрации синхронизируются с URL:

- Статусы (множественный выбор)
- Категория
- Диапазон цен
- Поиск по названию
- Сортировка
- Пагинация

### 2. Навигация между объявлениями

На странице детального просмотра реализована навигация "Предыдущее/Следующее":

- Кнопки перехода к соседним объявлениям
- Сохранение контекста фильтров при навигации
- Предзагрузка данных для плавных переходов

### 3. Обработка ошибок

Реализована система обработки ошибок:

- Toast-уведомления для всех API операций
- Специальные компоненты для отображения ошибок загрузки
- Типизированные ошибки с fallback на дефолтные сообщения
- Различные стратегии для критических и некритических ошибок

### 4. Оптимизация производительности

- **Дебаунс поиска и фильтр по диапазону цен** — задержка для уменьшения количества запросов
- **Мемоизация** — использование `useMemo` и `useCallback` для оптимизации ререндеров
- **RTK Query кеширование** — минимизация повторных запросов к API

### 5. UX улучшения

- **Skeleton loaders** — плейсхолдеры для улучшения восприятия загрузки
- **Плавные анимации** — использование Framer Motion
- **Адаптивный дизайн** — корректное отображение на всех устройствах
- **Темная тема** — комфортная работа в любое время суток
- **Автоматический скролл** — переход к началу страницы при смене роута

### 6. Валидация и типизация

- Полная типизация TypeScript для всех компонентов и функций
- Валидация форм модерации (обязательное указание причины)
- Type-safe API endpoints и responses
- Константы для статусов, категорий и т.д.
- Маппинг данных
